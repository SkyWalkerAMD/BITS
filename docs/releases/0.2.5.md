# BITS 0.2.5：识别现有网络并配置服务

本版面向新完整系统，管理端、节点端继续提供 RPM/DEB。旧 OCRUN 使用的 BITS-o 0.1.2 不需要因本次网络向导升级。原生 sckocp、激活规则、本地接口、压测工具与采集/报表实现保持现有版本。

## 新入口

root 在新管理服务器执行：

```bash
bits-center network
bits-center setup --auto --check
bits-center setup --auto --apply
bits-center check
```

- 自动识别处于启用状态的内网 IPv4 和子网；`network --json` 保留机器可读输出。
- 单个候选直接生成服务地址和允许网段，多网卡需 `--interface`，同卡多地址再指定 `--address`。
- 预检显示所选 IP、来源网段、三个 TCP 端口及动态地址提示。网卡地址、网关、路由、DNS 不由此功能改动。
- 常见容器/隧道接口、回环、链路本地、公网或未启用地址不进入自动候选；过大的自动网段要求显式指定范围。
- 发现网络变化、地址不明确时在安装器运行前停止。应用复用已有的服务身份、范围防火墙、认证、配置完整性与失败回滚保护。

安装、账户、凭据导出和部署流程见 [部署手册](../deployment/BITS.md)。连接文件仍通过可信方式交给对应节点；不提供广播发现或自动向任意节点发送凭据。

## 升级与回滚

新部署直接使用 bits-center / bits-node 0.2.5。完整节点已包含工具，不再安装 bits-o-workloads。

已经配置的完整系统须在维护窗口确认节点任务和收尾结束，节点停止调度并 `bits-node detach`，管理端 `bits-center rollback` 后按原包管理流程移除旧包、安装新版，再重新配置。管理端回滚会暂时停止任务库、资源和日志服务，因此不可在仍有节点运行任务时操作。

保存旧 RPM/DEB、SHA256SUMS、私有连接文件及配置备份。回滚沿用显式解除配置、移除新包、安装已核验旧包的流程，保留结果和原凭据。未知文件修改会阻止覆盖；不使用强制替换。没有为本功能增加在线修改 IP 或自动迁移已配置网段的行为。
