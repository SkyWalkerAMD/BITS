# BITS 0.3.0 候选：统一核心和独立运行目录

完整系统使用 bits-center / bits-node；旧 OCRUN 使用 bits-o-control / bits-o-node。
共享实现集中到 bits_core，核心采集、执行、收尾和报告不再维护两份代码。

- 完整节点使用 /opt/bits、/etc/bits、/var/lib/bits 和 /var/log/bits；内部采集与批次入口独立命名。
- 完整管理端使用 /srv/bits/results、/srv/bits/resources 和 bits-center-* 服务。
- 旧系统适配保留原 occt 下发、目录、锁与挂钩；原脚本基线保持字节一致。
- 固定并校验每种包的运行目录配置，完整节点缺少工具绑定时拒绝执行。
- Redis、rsync 和历史监控/报告 JSON 格式保持兼容，不改写已交付结果。
- sckocp 本体、授权边界、Primary 时序限制和未知数据质量说明保持不变。

跨目录升级必须显式分离旧部署，并保留原包与状态；不覆盖正在运行的节点。
构建、故障模拟、跨系统安装和回滚只在私有 Linux Actions 执行。
当前文件是候选说明，最终支持范围和验证结论以交付包 RELEASE.json 为准。

实现边界见[核心重构说明](../development/CORE-REFACTOR.md)。
