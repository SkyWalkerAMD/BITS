# 独立 sckocp-api 0.3.2 安全审查（2026-09-30）

## 范围和结论

本轮检查独立接口的启动、安装、原生调用、数据解析、输出及发布内容。维持原 sckocp 1.1.0/1.2.0，默认 v1，无网络监听，不修改授权、平台令牌或离线租约规则。没有对生产机器执行漏洞探测，也不把代码审查等同于保证没有其他漏洞。

Python 包本来就可阅读，无须反编译。接口不拥有激活签名私钥，阅读转换与调用代码本身不能产生合法授权。设备 root 用户仍能读取/替换本地程序、调试进程或伪造本机显示；保留未修改原版 sckocp 与离线授权的前提下，无法由外置 API 消除此边界。加密字符串、混淆、去符号、改成二进制均不是可靠的本机授权根。

用户随后同意扩展本体审查，维护者源码仓库另有 `docs/security/SCKOCP-NATIVE-SECURITY.md`（不随独立 API 包分发）。本体候选补丁与本独立 API 发行包分开，原版仍可由接口使用；补丁的验证和硬件保护架构不能用本轮接口测试替代。

## 问题、前提和处理

|问题|前提与影响|0.3.2 处理|
|---|---|---|
|运行前没有核对接口模块|接口目录被错误放宽权限或模块被替换后，旧命令仍直接导入；不是无需权限的远程攻击|启动器中固定模块指纹，导入前验证权限/类型/单链接/哈希；失败关闭|
|已有字节码仍可能加载|旧 `-B` 仅禁止写 `.pyc`；缓存被替换后，可在源码哈希不变时改变加载内容|从已核验的源码字节加载模块，忽略 API 字节码缓存|
|额外 Python 启动钩子|`-I` 不关闭系统 site 的 `.pth`/sitecustomize；受信任安装环境被污染会先运行钩子|独立命令和离线安装 Python 使用 `-S`，仍要求系统解释器和标准库可信|
|成功路径的辅助进程遗漏|原生程序退出成功但辅助进程关闭输出后仍运行，旧接口会直接返回|成功和失败均清理原隔离会话；在 PID 未回收前核对退出和清理|
|插件停止时的重复信号|监督进程释放锁后尚未退出，兼容扫描再次发送 TERM 可覆盖正常收尾退出码|0.12.11 的旧进程扫描跳过监督入口；由核对身份的监督停止流程处理，并以延长真实退出窗口的夹具回归|
|归档工具继承环境选项|运行安装器的环境携带 TAR_OPTIONS 等配置时可改变解包行为|解包前清除归档工具选项及 shell 路径相关环境；不宣称可撤销 bash 启动前执行的 BASH_ENV 或动态加载器行为|

前四项对应 `sckocp_api/bootstrap.py`、`install.py`、`provider.py`；归档检查位于 `templates/self-extract.sh.in`。现有可执行文件目录检查、FD 固定、JSON 字节/深度/数值限制、授权失败不复用读数、stderr 不外传均保留。

## 信任边界

- 管理安装的命令本身、Python 解释器及标准库由管理员保护。运行核验器不是第三方数字签名，不防能够一起替换这些部件的人。
- 独立 CLI 先核验再执行；SDK 导入和解压目录运行由调用方维护代码加载环境，不自动获得此启动器保护。
- 接口只传递监控参数，使用原生授权退出码；不读授权文件，不引入“已激活”缓存，不修改 C 实现。
- 本地 stdout 监控数据不是硬件远程证明。v1 有效性/读数年龄未知，缺失值不填 0。
- API 发布使用明确文件清单；不包含 C 实现、签名器、生产私钥或 drafts。整个开发仓库源代码与客户独立接口安装包的内容不同。
- 不开放任意 `--binary` 的免密 root sudo 入口。接口不提供提权代理。

## 验证与发布

云端隔离测试覆盖：可执行但被篡改的字节码缓存、修改模块和 manifest、权限漂移、链接/FIFO/缺文件、检查后路径替换、额外 site 钩子、成功/超时的辅助进程清理，以及既有授权拒绝与解析边界回归。另从已发布 0.3.1 包布局升级并恢复到旧安装器，验证备份和七文件运行目录兼容。

具体测试数量、源码提交、系统及通过状态由本次随包 `VALIDATION.json` 与 GitHub Actions 记录提供。未执行的测试不计为通过。传感器与临时签名授权使用隔离夹具，真实硬件验收仍需另做。

安装升级使用 `bash sckocp-api-0.3.2.run --check`，通过后再执行同包不带 `--check`。安装不执行 sckocp，不改变激活状态。保留安装输出的 `backup` 与 `command_backup`；需要退回 0.3.1 时使用已核验来源的原 0.3.1 安装器，其文件布局仍兼容。手工修改过的安装会拒绝覆盖，需先保留证据并排查。

原 `ocrun-plugin` 和完整系统 Release 是固定快照，不会因升级独立 API 自动改变。共享采集进程修复另随 `mon-sensors-plugin 0.12.11` 提供，不能把单独 API 的启动器保护描述为所有 SDK 宿主均已启用。
